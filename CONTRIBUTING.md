# Contributing

Thanks for helping improve Lensmor's public trade show resources.

Before opening a pull request:

- Check whether the change belongs in the target repository.
- Prefer official event, venue, organizer, or vendor sources when adding factual data.
- Keep descriptions concise and verifiable.
- Include source links for non-obvious claims.
- Avoid adding promotional copy that does not help users evaluate trade shows, exhibitors, tools, or workflows.

For data-oriented repositories, explain what changed and why the source is reliable. For templates or playbooks, include the user workflow the change supports.

## Choose a contribution

- **Event data:** correct an edition, date, or location in [trade-show-calendar](https://github.com/LensmorOfficial/trade-show-calendar). Update both CSV and JSON and link the organizer's page.
- **AI workflows:** improve a skill or worked example in [trade-show-skills](https://github.com/LensmorOfficial/trade-show-skills). Follow its own contribution guide and run `bash scripts/validate-repo.sh`.
- **API documentation:** clarify a request or response in [API-Doc](https://github.com/LensmorOfficial/API-Doc). Follow its README checks before opening a PR.
- **Resource discovery:** suggest a sourced show or tool in [awesome-trade-shows](https://github.com/LensmorOfficial/awesome-trade-shows) or [event-tech-landscape](https://github.com/LensmorOfficial/event-tech-landscape).

One corrected fact, broken link, or clearer example is a useful contribution. Keep PRs focused enough to verify independently.

For bugs, explain the reproduction steps and expected result. For factual corrections, include the official source, edition year, and date you checked it. Use the issue chooser in the affected repository.

Repository-specific instructions take precedence over these defaults. See [SUPPORT.md](SUPPORT.md) for product and account questions.
